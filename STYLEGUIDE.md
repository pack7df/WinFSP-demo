# Project Standards

## 📝 Language & Documentation

All project documentation must be written in **technical English**, following professional software engineering standards.

This includes:
- README files
- Code comments (where appropriate)
- Configuration files with descriptions
- API documentation
- Git commit messages
- Developer guides
- Inline documentation

### Style Guidelines
- Use clear, concise technical English
- Follow industry terminology
- Maintain professional tone
- Avoid colloquialisms or regional expressions
- Use active voice when possible
- Keep documentation up-to-date with code changes

### Scope
This rule applies to all files in the repository, regardless of the language used in:
- Issue trackers
- Chat conversations
- Meetings
- Non-documentation communications

The codebase itself (variable names, function names, etc.) should also use English naming conventions.

---
*Note: This is a hard requirement for maintaining a professional, internationally accessible codebase.*
